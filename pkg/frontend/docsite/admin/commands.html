Commands

Server commands

Command Description
serve Run everything in one process: pages, API, database and keys.
serve web Run the frontend of a split deployment: pages, static files and the public HTTP, HTTPS and HTTP/3 listeners. No database.
serve api Run the backend of a split deployment: database, keys, public API, internal API and maintenance.
serve worker Run a worker: it talks to Withings, Strength Level, the sign-in providers and the mail server for the api process. No database.
serve body Run the body service: scale readings, DEXA scans and estimates, in a database of its own.
healthcheck URL Make one GET request and exit 0 if the answer is 2xx, 1 otherwise. For the container health check: the image has no shell and no curl. See Status and health checks.
secrets service-secret Print a new service secret of 64 hexadecimal characters for serve web and serve api.
secrets worker-secret Print a new worker secret of 64 hexadecimal characters for serve api and the workers of one provider (make one for each provider). It must differ from the service secret and from the other providers' secrets.
secrets body-secret Print a new body secret of 64 hexadecimal characters for serve api and serve body. It must differ from the service and worker secrets.
secrets body-token-key Print a new private key for the api process to sign body service tokens with. Keep it to that process.
secrets body-token-public --key-file FILE Print the public key of that private key, for serve body.
secrets init Create every secret and the mutual TLS certificates of the Compose deployment in directories you name (--host-dir, --api-dir, --web-dir, --worker-dir PROVIDER=DIR once for each provider, --body-dir, and --db-dir, --dbsetup-dir, --valkey-dir for the database, db-setup and Valkey containers). The api and body directories also get their connection string and encryption key. It never replaces a password, key or shared secret that exists, and makes new certificates at every run (--mtls-days, default 397). --chown uid:gid hands the files to the containers' user. It also makes the password and URL of the optional Valkey server (--valkey-host). This is what the init container runs.
secrets mtls Create certificates for mTLS. With --link body, for the link between the api process and the body service.

Create the service secret file and keep it private:

go run . secrets service-secret > service.secret && chmod 600 service.secret

A group- or world-readable file only logs a warning. See Service secret for rotating it.

Database commands

Command Description
db migrate [up] Apply all pending migrations. This is the default action.
db migrate down --yes Roll back the latest migration. Drops tables and their data.
db migrate to N Migrate up or down to version N. 0 empties the schema. Going down needs --yes.
db migrate status List every migration and whether it is applied.
db migrate version Print the current schema version.
db copy Copy all data to another database. See below.
db provision Make the PostgreSQL roles dexafix_owner (owns the database, cannot log in), dexafix and dexafix_body, the database dexafix and the schema body that the Compose deployment runs on, as the administrator (--admin-dsn-file, --app-password-file, --body-password-file). It can be repeated (two runs at once wait for each other): what exists is kept, the roles lose extra attributes (superuser, create-role and the like) and memberships, a database owned by dexafix goes to dexafix_owner, the passwords are set again (as SCRAM verifiers, so they are not in a logged statement; 16 characters or more are recommended, a shorter one works with a warning), nothing is dropped. PostgreSQL only. This is what the db-setup container runs.
db rekey [--dry-run] [--body] Re-encrypt all encrypted values with the current key. With --body, the readings and scans of a body service's own database. See Encryption.

db migrate takes --db-driver and --dsn, with the same environment variables as serve. db copy takes --from-driver, --from-dsn, --to-driver and --to-dsn, with the variables DEXAFIX_FROM_DSN, DEXAFIX_TO_DRIVER and DEXAFIX_TO_DSN (and *_FILE variants for the connection strings). --from-dsn falls back to DEXAFIX_DSN.

Rolling back drops the tables and columns of the migrations it undoes, together with their data. db migrate down and db migrate to N for an N below the current version therefore refuse to run without --yes; without it they print which migrations would be undone. Make a backup first. db rekey takes the database and encryption key flags of serve. When a body service has its own database, give the db, user and settings commands --without-body for the main database.

go run . db migrate status
DEXAFIX_DSN=postgres://user:pass@localhost/dexafix go run . db migrate up --db-driver postgres
go run . db migrate down --yes

Account commands

Command Description
user reset-2fa <e-mail> Remove two-step verification and the recovery codes of that account.

user reset-2fa is for lockouts, when nobody who can sign in can turn it off from the Admin page. It works on the database directly, so it takes the same database and encryption key settings as serve: --db-driver, --dsn (or DEXAFIX_DSN, or --dsn-file) and the key flags. The server does not have to be stopped, but the change is not written to the audit log. If an administrator requires two-step verification, the user sets it up again at the next sign-in.

DEXAFIX_DSN=postgres://user:pass@localhost/dexafix go run . user reset-2fa you@example.com --db-driver postgres

Settings recovery

Command Description
settings reset-network Clear the base URL, the trusted proxies and the PROXY protocol setting.

Use it when a saved value leaves the Admin page unreachable: a base URL for an address you no longer use, or a PROXY protocol setting that stops your balancer from connecting. It works on the database directly, so it takes the same database and encryption key settings as serve: --db-driver, --dsn (or DEXAFIX_DSN, or --dsn-file) and the key flags. The change is not written to the audit log. Restart the server afterwards, because a running server reads these settings at start and when they are saved on the Admin page.

DEXAFIX_DSN=postgres://user:pass@localhost/dexafix go run . settings reset-network --db-driver postgres
